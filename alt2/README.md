# أدوات استخراج حزم ALT2

## نسخة C++ المبنية بواسطة Visual Studio

تتوفر أداة C++17 مستقلة موصى بها على Windows، لا تحتاج إلى Python أو مكتبات خارجية:

- [مشروع Visual Studio 2022 وتعليمات البناء والتشغيل](cpp/README.md)
- الحل: [`cpp/Alt2Unpacker.sln`](cpp/Alt2Unpacker.sln)
- المصدر: [`cpp/main.cpp`](cpp/main.cpp)

تكتشف مفتاح XTEA-4 من العميل استاتيكيًا، وتمسح مجلد `pack` إذا وُجد وإلا `data` (بشكل متداخل) بحثًا عن أرشيفات ALT2، ثم تتيح اختيار حزمة بالاسم أو فكّ الجميع. تتحقق من الحجم وXXH32 لكل ملف. على العينة المرفقة اجتازت الملفات الـ894 التحقق، وطابقت أسماء الملفات الـ337 التي تستنتجها نسخة Python المرجعية. لا تشغّل العميل أو المحتوى المستخرج ولا تعدّل ملفات الإدخال.

## نسخة Python المرجعية

`unpack.py` يفك تشفير الحزمة، ويفك ضغط محتوياتها، ويتحقق من سلامة كل ملف قبل نشر مجلد النتائج. يقرأ ملف العميل قراءة ثابتة فقط؛ **لا يشغّل `metin2client.exe` أو أي سكربت مستخرج**، ولا يعدّل ملفات الإدخال.

## متطلبات نسخة Python والتثبيت

Python **3.10+** على Windows أو Linux أو macOS. نفّذ الأوامر من جذر المستودع `Unpack-client`.

### Windows — PowerShell

```powershell
py -3 -m venv .venv
.venv\Scripts\python.exe -m pip install -r alt2/requirements.txt
.venv\Scripts\python.exe alt2/unpack.py key
.venv\Scripts\python.exe alt2/unpack.py extract
```

### Linux / macOS

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r alt2/requirements.txt
.venv/bin/python alt2/unpack.py key
.venv/bin/python alt2/unpack.py extract
```

في بقية الأمثلة، استبدل `python` بمسار Python داخل البيئة الافتراضية عند الحاجة. لا تعتمد المسارات الافتراضية للعميل والحزمة على مجلد التشغيل؛ تُحسب نسبةً إلى مكان السكربت.

## الأوامر

```bash
# اكتشاف المفتاح وموقعه داخل EXE، مع بصمة SHA-256 للعميل
python alt2/unpack.py key

# عرض فهرس الملفات وأحجامها دون فك المحتوى
python alt2/unpack.py list

# فك جميع الملفات والتحقق من أحجامها وبصماتها دون حفظها
python alt2/unpack.py verify

# استخراج root إلى المجلد الافتراضي alt2/unpacked/root
python alt2/unpack.py extract

# تحديد الحزمة والعميل ومجلد إخراج جديد
python alt2/unpack.py extract alt2/data/root --client alt2/metin2client.exe -o alt2/unpacked/root-new

# توفير قائمة أسماء إضافية؛ يمكن تكرار --names
python alt2/unpack.py extract --names names.txt -o alt2/unpacked/root-with-names
```

**مجلد الإخراج يجب ألا يكون موجودًا.** عند إعادة التجربة اختر اسمًا جديدًا باستخدام `-o`. الأداة ترفض الكتابة فوق نتائج سابقة أو مسار إخراج عبارة عن رابط رمزي.

أمر `list` يعرض أسماء مرشحة من العميل وقوائم الأسماء فقط؛ قد يستعيد `extract` أسماء إضافية من محتوى الملفات بعد فكها. قائمة `list` لا تعني نجاح التحقق من المحتوى؛ استخدم `verify` لذلك.

يمكن تمرير حزم أخرى إلى الأداة، لكن **الاختبار الفعلي شمل `data/root` المرفقة فقط**. أي إصدار عميل لا تطابقه بصمة روتين فك التشفير سيُرفض بدل تخمين موقع المفتاح.

## أين توجد الملفات؟

```text
alt2/unpacked/root/
├── files/                 # الملفات ذات الأسماء المستنتجة
│   ├── game.py
│   ├── ui.py
│   ├── constinfo.py
│   ├── skill_tree/board/top.tga
│   └── ...
├── unknown/               # محتوى مفكوك بالكامل لكن الاسم غير معروف
│   ├── 0014_e5abfd6e.py   # الامتداد من كشف نوع المحتوى
│   ├── 0037_885750a9.avi
│   └── 0203_0ef95bf3.png
└── manifest.json          # الفهرس والأسماء والبصمات والأحجام ومسارات الإخراج
```

الأرشيف لا يخزن الاسم ولا الامتداد؛ كل الملفات المكتوبة اجتازت التحقق من المحتوى وتُكتب بايت ببايت دون إعادة ترميز. الملفات غير المسماة تحصل على امتداد من **كشف نوع المحتوى** (بصمات PNG/JPG/DDS/TGA/RIFF/Ogg/Granny وأنماط نصوص Python وXML وسكربتات MSM/MSA) بدل امتداد `.bin` العام؛ يبقى `.bin` فقط للمحتوى غير المعروف. حقل `detected_type` في `manifest.json` يوثّق هذا الكشف لكل ملف غير مسمى.

الأرشيف يخزن **CRC32 للاسم** لا الاسم نفسه، ولذلك لا يمكن استرجاع كل الأسماء من رؤوس الملفات وحدها. الأداة تستخرج أسماء مرشحة من نصوص العميل، ومراجع الملفات، وعبارات استيراد Python، وتجميعات نصية بسيطة دون تنفيذها. بعد فك كل المحتوى تضيف مرحلة **توليد محدود** مرشحات إضافية: دمج المجلدات المرصودة مع الأسماء العارية من أي ملف (`skill_tree/board/` + `top.tga`)، وتعداد الأسماء القصيرة جدًا (حرفان فأقل) مع الامتدادات الشائعة (`skill_tree/direction/7.tga`)، وإقران معرفات النصوص بالامتدادات (`SkyBoxChanger` + `.py`). لا يُقبل أي مرشح إلا عند مطابقة CRC32. هذه المطابقة دليل عملي وليست ضمانًا رياضيًا للاسم الأصلي؛ قد تحدث تصادمات CRC32. عند وجود أكثر من مرشح للبصمة نفسها يُحفظ الملف ضمن `unknown/` وتُذكر المرشحات في الفهرس.

الأسماء المستنتجة صغيرة الأحرف لأن العميل يحوّل الأسماء إلى lowercase قبل حساب بصمتها. المسار الافتراضي مثل `d:/ymir work/...` يُحفظ بأمان داخل `files/_drives/d/ymir work/...` وليس خارج مجلد الإخراج.

لتحسين الاسترجاع أضف أسماء محتملة إلى ملف UTF-8، اسمًا في كل سطر:

```text
# names.txt
introempire.py
uiinventory.py
itemshop/mainpage/middle/bg.png
```

هذا خيار لإعادة تسمية الملفات بناءً على بصماتها، وليس ضروريًا لفك محتواها.

## السلامة والحدود

- XTEA بأربع دورات، ثم LZ4 عند الحاجة، ثم مطابقة الحجم وXXH32 لكل ملف.
- فحص توقيع الحزمة، والرؤوس، والمحاذاة، والإزاحات وحدود الملف قبل فك البيانات.
- يمنع تجاوز المسارات مثل `../`، ومسارات النظام المطلقة، والأسماء المحجوزة في Windows.
- تُكتب النتائج أولًا في مجلد مؤقت؛ عند الفشل يُحذف، ولا يُنشر مجلد الإخراج النهائي.
- حدود افتراضية: 128 MiB للملف و1 GiB للمجموع غير المضغوط. يمكن تعديلها بالبايت باستخدام `--max-file-size` و`--max-total-size` للمدخلات الموثوقة.
- لا تتضمن الأداة إعادة الحزم، أو إعادة التشفير، أو فك bytecode إلى مصدر، أو ضمان استرجاع جميع الأسماء.
- الملفات المستخرجة والبيئة الافتراضية وملفات التحليل المؤقتة مستبعدة من Git؛ يمكن إعادة توليد النتائج بالأمر نفسه.
