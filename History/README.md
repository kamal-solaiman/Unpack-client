# أداة استخراج حزم History

`unpack.py` يفك تشفير الحزمة `History/pack/workplace.d2`، ويفك ضغط محتوياتها، ويتحقق من سلامة كل ملف قبل نشر مجلد النتائج. يقرأ `History2.exe` قراءة ثابتة فقط؛ **لا يشغّل العميل ولا أي سكربت مستخرج**، ولا يعدّل ملفات الإدخال.

الصيغة هنا **AES-256-CFB ثم LZ4 ثم فحص XXH32**، وهي مختلفة تمامًا عن صيغة ALT2 في هذا المستودع (XTEA-4). التفاصيل الكاملة والأدلة في [FORMAT.md](FORMAT.md).

## من أين يأتي المفتاح؟

على عكس عينة ALT2، مفتاح هذه الحزمة **مخزّن داخل رأس الحزمة نفسها** (32 بايت عند الإزاحة `0x04` ومتجه التهيئة 16 بايت عند `0x24`). دور `History2.exe` أنه يحدّد كيف يُقرأ هذا الرأس: السحر `0xF00FED5C`، وحجم الرأس `0x44`، وطول المفتاح 32 بايت (أي AES-256)، وموضع متجه التهيئة، ونوع الوضع CFB، وبصمة CRC32 للأسماء، وبذرة XXH32.

لذلك لا تثبّت الأداة أي رقم يدويًا: `analyze_client()` تستخرج السحر وهندسة الرأس من تعليمات الآلة نفسها (سلسلة XXH32 ← بذرة الهاش ← مقارنة السحر ← نسخ الرأس بـ `movups` ← سلسلة وسائط بناء Cipher)، وترفض أي إصدار عميل لا تُثبت شيفرته هذه الهندسة بدل التخمين. ثم تؤكد النتيجة عمليًا بفك أول ملفات والتحقق من بصماتها.

يدعم العميل أيضًا قناعَي XOR اختياريين (32 بايت لكل منهما) مرتبطين باسم الحزمة في جدول داخلي؛ يمرّر `NULL` عندما لا يوجد الاسم في الجدول. الاسم `workplace` **غير موجود إطلاقًا** في `History2.exe`، فلا قناع يُطبق، وقد تأكد ذلك عمليًا بنجاح التحقق لكل الملفات الـ813. إن احتجت حزمة أخرى مقنّعة فاستخدم `--key-mask` و`--iv-mask` بقيم ست عشرية.

## المتطلبات والتثبيت

Python **3.10+** على Windows أو Linux أو macOS. نفّذ الأوامر من جذر المستودع `Unpack-client`.

### Windows — PowerShell

```powershell
py -3 -m venv .venv
.venv\Scripts\python.exe -m pip install -r History/requirements.txt
.venv\Scripts\python.exe History/unpack.py key
.venv\Scripts\python.exe History/unpack.py extract
```

### Linux / macOS

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r History/requirements.txt
.venv/bin/python History/unpack.py key
.venv/bin/python History/unpack.py extract
```

الحزم المطلوبة: `lz4` و`xxhash` و`pycryptodome`. في بقية الأمثلة استبدل `python` بمسار Python داخل البيئة الافتراضية عند الحاجة. المسارات الافتراضية للعميل والحزمة ومجلد الإخراج تُحسب نسبةً إلى مكان السكربت، لا إلى مجلد التشغيل.

## الأوامر

```bash
# اشتقاق هندسة الصيغة من EXE وقراءة مفتاح الحزمة والتحقق منه عمليًا
python History/unpack.py key

# عرض فهرس الملفات وأحجامها وإزاحاتها دون فك المحتوى
python History/unpack.py list

# فك جميع الملفات والتحقق من أحجامها وبصماتها دون حفظها
python History/unpack.py verify

# استخراج workplace.d2 إلى المجلد الافتراضي History/unpacked/workplace
python History/unpack.py extract

# تحديد الحزمة والعميل ومجلد إخراج جديد
python History/unpack.py extract History/pack/workplace.d2 --client History/History2.exe -o History/unpacked/workplace-new

# قائمة أسماء إضافية (يمكن تكرار --names) ومجلدات إضافية للبحث (يمكن تكرار --prefix)
python History/unpack.py extract --names names.txt --prefix uiscript/ -o History/unpacked/workplace-named
```

**مجلد الإخراج يجب ألا يكون موجودًا.** عند إعادة التجربة اختر اسمًا جديدًا باستخدام `-o`. الأداة ترفض الكتابة فوق نتائج سابقة أو فوق مسار إخراج عبارة عن رابط رمزي.

أمر `list` يعرض أسماء مرشحة من نصوص العميل وقوائم الأسماء فقط؛ `extract` يستعيد أسماء إضافية من محتوى الملفات بعد فكها (مثل `uiscript/`)، لذلك عدد الأسماء في `extract` أكبر. قائمة `list` لا تعني نجاح التحقق من المحتوى؛ استخدم `verify` لذلك.

يمكن تمرير حزم `.d2` أخرى إلى الأداة، لكن **الاختبار الفعلي شمل `pack/workplace.d2` المرفقة فقط**.

## أين توجد الملفات؟

```text
History/unpacked/workplace/
├── files/                 # الملفات ذات الأسماء المستنتجة
│   ├── ui.py
│   ├── game.py
│   ├── interfacemodule.py
│   ├── uiscript/          # 340 ملف تخطيط نوافذ
│   └── ...
├── unknown/               # محتوى مفكوك بالكامل لكن الاسم غير معروف
│   └── 0468_ff6e5d2d.bin
└── manifest.json          # الفهرس والأسماء والمرشحات والبصمات والأحجام ومسارات الإخراج
```

امتداد `.bin` للملفات غير المسماة لا يعني استمرار تشفيرها؛ هو امتداد محايد لأن الأرشيف لا يخزن الاسم أو الامتداد. جميع الملفات المكتوبة اجتازت التحقق من الحجم وبصمة XXH32. لا تعيد الأداة ترميز النصوص أو تحويل نهايات الأسطر.

## استرجاع الأسماء

الأرشيف يخزن **CRC32 للاسم** (بعد تحويل الأحرف إلى lowercase واستبدال `\` بـ `/`) لا الاسم نفسه. تجمع الأداة مرشحات من مصدرين:

1. نصوص العميل `History2.exe` (ASCII وUTF-16)، وتضم مسارات سكربتات حقيقية مثل `uiscript\beltinventorywindow.py`.
2. محتوى الملفات بعد فكها: المسارات النصية، وعبارات `import`، والمعرّفات، والمجلدات التي تكشفها (مثل `uiscript/`) فتُستخدم لتجربة أسماء الوحدات المجردة.

لا يُقبل الاسم إلا عند مطابقة CRC32 لبصمة موجودة في الفهرس، وعند وجود أكثر من مرشح للبصمة نفسها يبقى الملف في `unknown/` وتُذكر المرشحات في `manifest.json`. هذه المطابقة دليل عملي وليست ضمانًا رياضيًا؛ تصادمات CRC32 واردة نظريًا. لتحسين الاسترجاع أضف أسماء محتملة إلى ملف UTF-8، اسمًا في كل سطر:

```text
# names.txt
uiscript/uigameoption.py
docs/UI_FUNDAMENTALS.md
```

هذا خيار لإعادة تسمية الملفات بناءً على بصماتها، وليس ضروريًا لفك محتواها.

## السلامة والحدود

- فك AES-256-CFB (متجدد لكل ملف كما يفعل العميل)، ثم LZ4 عند الحاجة، ثم مطابقة الحجم وXXH32 لكل ملف.
- فحص سحر الحزمة، والرؤوس، والإزاحات، وحدود الملف، وتسلسل السجلات حتى نهاية الأرشيف قبل فك البيانات.
- يمنع تجاوز المسارات مثل `../`، والمسارات المطلقة، وأسماء الأجهزة المحجوزة في Windows.
- تُكتب النتائج أولًا في مجلد مؤقت؛ عند الفشل يُحذف، ولا يُنشر مجلد الإخراج النهائي.
- حدود افتراضية: 128 MiB للملف و1 GiB للمجموع غير المضغوط. يمكن تعديلها بالبايت باستخدام `--max-file-size` و`--max-total-size` للمدخلات الموثوقة.
- لا تتضمن الأداة إعادة الحزم، أو إعادة التشفير، أو فك bytecode إلى مصدر، أو ضمان استرجاع جميع الأسماء.
- الملفات المستخرجة والبيئة الافتراضية مستبعدة من Git؛ يمكن إعادة توليد النتائج بالأمر نفسه.
